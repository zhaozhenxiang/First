# PHP `parse_str()` 字符行为完整分析

> 测试环境: PHP 8.5.3 (cli) NTS, Linux x86_64
> 测试日期: 2026-03-27
> 测试脚本: `test_parse_str.php` / `test_parse_str_utf8.php` / `test_parse_str_charset.php`

## 核心结论

`parse_str()` 是**纯字节操作**函数，不进行任何编码验证或转换。它只识别以下 URL 语法分隔符：

| 字节 | 字符 | 作用 | 变量名影响 | 值影响 |
|------|------|------|-----------|--------|
| `0x00` | NUL | 字符串终止 | 丢失 | 通过 `%00` 正常 |
| `0x26` | `&` | 变量分隔符 | 截断 | 通过 `%26` 正常 |
| `0x3D` | `=` | 键值分隔符 | 截断 | 通过 `%3D` 正常 |
| `0x2B` | `+` | 值中的空格缩写 | 转换为 `_` (变量名) / `SPC` (值) | 通过 `%2B` 正常 |
| `0x20` | SPC | 空格 | 转换为 `_` | 通过 `+` 或 `%20` 正常 |
| `0x2E` | `.` | 嵌套数组语法 | 转换为 `_` | 通过 `%2E` 正常 |
| `0x5B` | `[` | 数组索引开始 | 丢失(需配对 `]`) | 通过 `%5B` 正常 |

**编码/字符集设置完全不影响 `parse_str()` 的行为。**

### 5.2 不同编码字节输入

`parse_str()` 对字节透明——任何编码的字节序列只要不含分隔符就原样保留：

| 字符 | UTF-8 | GB18030 | BIG-5 | CP932 | EUC-JP |
|------|-------|---------|-------|-------|--------|
| 中 | `E4 B8 AD` | `D6 D0` | `A4 A4` | `92 86` | `C3 E6` |

| é | `C3 A9` | `A8 A6` | - | - | - |
| € | `E2 82 AC` | `A2 E3` | - | - | - |

所有编码的字节均原样保留。

## 六、GBK/Big5 字节冲突（安全问题）

GBK 编码第二字节范围 `0x40-0x7E, 0x80-0xFE`，其中部分值与 URL 分隔符冲突：

| 构造字节 | 冲突字符 | 变量名行为 | 说明 |
|----------|----------|-----------|------|
| `81 26` | `&` | **被截断为 `81`** | 解析出 2 个变量 |
| `81 3D` | `=` | **被截断为 `81`** | 被当作空值的键 |
| `81 2B` | `+` | `81 5F 74 65 73 74` | `+` 转换为 `_` (0x5F) |
| `81 20` | SPC | `81 5F 74 65 73 74` | 空格转换为 `_` |
| `81 5B` | `[` | `81 5F 74 65 73 74` | `[` 转换为 `_` |
| `81 23` | `#` | `81 23 74 65 73 74` | 正常保留 |
| `81 5D` | `]` | `81 5D 74 65 73 74` | 正常保留 |
| `81 25` | `%` | `81 25 74 65 73 74` | 正常保留 |
| 真实 GBK "中" | - | `D6 D0 74 65 73 74` | 正常保留 |
| 真实 GBK "啊" | - | `B0 A1 74 65 73 74` | 正常保留 |

### 安全建议

GBK/Big5 多字节编码在 URL 解析场景中存在经典的**字符注入**风险：

```
# GBK 中 0x81 0x26 构成某字符，但 0x26(&) 被 parse_str 当作分隔符
# 导致攻击者可注入额外变量
```

**正确做法：所有非 ASCII 字节在传入 `parse_str` 前，必须先 `rawurlencode()` 编码。**

## 七、UTF-16/UTF-32 编码

UTF-16/UTF-32 因包含大量 `0x00` 字节，在变量名中会被严重截断：

| 编码 | 输入 | 结果 |
|------|------|------|
| UTF-8 BOM + 中文 | `EF BB BF E4 B8 AD ...` | 键名正常（UTF-8 无 NUL） |
| UTF-16LE BOM + 中文 | `FF FE 2D 4E 76 00 ...` | 截断于第一个 `0x00` |
| UTF-16BE BOM + 中文 | `FE FF 4E 2D 00 76 ...` | 截断于第一个 `0x00` |
| UTF-16LE 无BOM | `2D 4E 76 00 61 00 ...` | 截断于第一个 `0x00` |

## 总结

| 维度 | 结论 |
|------|------|
| **函数本质** | 纯字节级 URL 解析器，不感知编码 |
| **编码设置** | `mbstring.*` / `default_charset` 均不影响 |
| **合法 UTF-8** | 全部正常保留 (34/34) |
| **非法 UTF-8** | 字节级原样保留，仅 NUL 导致截断 |
| **值安全性** | 经 `rawurlencode` 后所有字节 100% 可还原 |
| **变量名风险** | NUL 截断、`&` 分隔、`=` 分隔、`+`/SPC/`.`/`[` 转换 |
| **GBK/Big5** | 第二字节冲突可被利用注入变量 |
| **最佳实践** | 变量名避免非 ASCII；值必须 `rawurlencode` |
